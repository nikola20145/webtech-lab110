Overview
Response code: 200 Response code: 404 Response code: 500
In the GET request the response code 200(OK) is displayed if the request succeeded. This can be an example of a response for a successful request : { "id": "4", "author": "Nikola Tesla", "alt": "Image of Nikola Tesla", "tags": "genius, noble, inventor", "image":"https://nationaltoday.com/wp-content/uploads/2022/06/22-Nikola-Vesla-640x514.jpg", "Description": "He created the light bulb." } In the GET request the 404(Not found) response code can appear two times. One time it would be if the user sends a GET request for an author with non-existent ID. It will give a output: { "error": "ID of author not found" }. The other time it would give an 404 (Not found) response code is when the URL in the request is bad. The output will be : { "status": 404, "success": false, "error": "Invalid URL request" }. In the GET request the 500(Internal Server Error) response code will appear when there is some problem within the server. It will give a output: { error: 'Error retrieving author' } 

        

        HTTP verb POST:
        CRUD Create:
        


        Endpoint URI: /api/authors
        HTTP method: POST
        Parameters: none required
        MIME format: json/application   - means that the data being transferred between the client and the server is in a JSON format.
        

                       
        Example request URL : http://localhost:3000/api/authors
        Example input in request body with a JSON input for creating a new author with response code 201 (Created)
        { 
            "author": "Jordan Peterson",
            "alt": "Image of Jordan Peterson",
            "tags": "intelligent, noble, philosopher",
            "image": "https://encrypted-tbn0.gstatic.com/images?q=tbn:ANd9GcTECC8Ci3GxrdatoKCKUwSBwUoKzvvGYdSWIw&usqp=CAU",
            "description": "The best philosopher of modern era who is trying to make the world a better place."
        }
        If succsesful the response would be :
        {
            "message": "Author created"
        }
        And if there is a invalid request with bad JSON input then it will give a response code 400 (Bad request).
        One example is with more properties than needed in the JSON input like this:
        { 
            "author": "Jordan Peterson",
            "alt": "Image of Jordan Peterson",
            "tags": "intelligent, noble, philosopher",
            "image": "https://encrypted-tbn0.gstatic.com/images?q=tbn:ANd9GcTECC8Ci3GxrdatoKCKUwSBwUoKzvvGYdSWIw&usqp=CAU",
            "description": "The best philosopher of modern era who is trying to make the world a better place.",
            "age": "60"
        }
        The response would be: 
        {
            "error": "Invalid request body, additional properties present"
        }
        
        Again if there is a invalid request with bad JSON input then it will give a response code 400 (Bad request).
        Another example is if in the input there are less properties than the original like this:
        { 
            "author": "Jordan Peterson",
            "alt": "Image of Jordan Peterson",
            "tags": "intelligent, noble, philosopher",
            "image": "https://encrypted-tbn0.gstatic.com/images?q=tbn:ANd9GcTECC8Ci3GxrdatoKCKUwSBwUoKzvvGYdSWIw&usqp=CAU"
        }

        So, without property "descripition" it will give a response code 400(Bad request) and output like this: 
        {
            "error": "Invalid request body, missing required properties"
        }

        There is another case where there may be Internal Server Error, it will give a response code 500(Internal Server Error)
        The output will be:
        
        {
            error: 'Error retrieving author'
        }

        We also made it so if there is a bad URL request in any kind of form that it would give a response code 404(Not found)
        and the output will be:

        {
            "status": 404,
            "success": false,
            "error": "Invalid URL request"
        }
Overview
Response code: 201 Response code: 400 Response code: 500 Response code: 400
In the POST request the response code 201(Created) is displayed if the request succeeded. This can be an example of a response output for a successful request : 
                {
                        "message": "Author created with ID: ${id}"
                }
In the POST request the 400(Bad Request) response code can appear two times. One time it would be if the user sends a POST request with JSON input that has more properties than the required. It will give a output: The response would be: { "error": "Invalid request body, additional properties present" } The other time it would give an 400 (Bad Request) response code is when the user sends a POST request with JSON input that has less properties than the required. The output will be : { "error": "Invalid request body, missing required properties" } In the POST request the 500(Internal Server Error) response code will appear when there is some problem within the server. It will give a output: { error: 'Error posting author' } The situation where it would give a 404 (Not found) response code is when the URL in the request is bad. The output will be : { "status": 404, "success": false, "error": "Invalid URL request" }. 
        

        HTTP verb PUT:
        CRUD Update:
        


        Endpoint URI: /api/authors/{id}
        
        HTTP method: PUT
        Parameters: id (required) for a specific author.
        MIME format: json/application - means that the data being transferred between the client and the server is in a JSON format.
        Example:

        200 OK
        The request succeeded. The result meaning of "success" depends on the HTTP method:
        PUT: The resource describing the result of the action is transmitted in the message body.

        
                       
                        Specific Item (e.g. /authors/{id})

        Example URL request : https://localhost:3000/authors/4
        Example input request in body with the json object :  
        {
            "author":"Albert Einstein", 
            "alt": "Image of Albert Einstein, 
            "tags": "genius, inventor", 
            "image":"https://encrypted-tbn0.gstatic.com/images?q=tbn:ANd9GcR514HXVtU9I5c4hChcxTYs7yLM3DtQcW8kQw&usqp=CAU",

        {
            "message": "Author updated"
        }

        The output will be:

        {
            "error": "Author not found"
        }
        
        Also if we have a request in body with JSON input like this :
        {

        The output will be:

Overview
Response code: 200 Response code: 400 Response code: 500 Response code: 404
In the PUT request the response code 200(OK) is displayed if the request succeeded. This will be a response output for a successful request to update an author : 
                {
                    "message": "Author updated"
                }
In the PUT request the 400(Bad Request) response code can appear two times. One time it would be if the user sends a PUT request with JSON input that has more properties than the required.         HTTP verb DELETE: 
        CRUD Delete:
        

        

        Endpoint URI: /api/authors/{id}
        HTTP method: DELETE
        Parameters: id (required) to delete a specific author

                            Specific Item (e.g. /authors/{id})

        https://localhost:3000/authors/12 -  If there exists an author with id 12, this delete request deletes the author with id = '12' and has repsonse code of 204 (No content).
        
        For example:  https://localhost:3000/authors/54 this will lead to a error (response code 404 (Not Found)), because there doesn't exist an author with id 54.
        Output will look like:

        {
            "error": "Author not found"
        }

        There is another case where there may be Internal Server Error, it will give a response code 500(Internal Server Error)
        The output will be:
        
        {
            error: 'Error retrieving author'
        }
        
        We also made it so if there is a bad URL request in any kind of form that it would give a response code 404(Not found)
        and the output will be:

        {
            "status": 404,
            "success": false,
            "error": "Invalid URL request"
        }
Overview
Response code: 204 Response code: 500 Response code: 404
In the DELETE request the response code 204(No Content) is displayed if the request succeeded. This, However won't give any output (No content). In the DELETE request the 500(Internal Server Error) response code will appear when there is some problem within the server. It will give a output: { error: 'Error deleting author' } There are two situations where it would give a 404 (Not found) response code. The first one would be when a user tries to delete an author with non-existing id. It will give an output like this: { "error": "Author not found" } The second situation where it would give a 404(Not Found) is when the URL in the request is bad. The output will be : { "status": 404, "success": false, "error": "Invalid URL request" }.

Overview
Reset Reset - response code 204(No Content) Reset - response code 500(Internal Server Error)
For the bonus, we added a GET request that will work with reseting (deleting), all the authors that the user has created. This works correspondingly as for the assignment 2. The user cannot delete the first 13 authors because they are a part of the data base which the user cannot access. If the user sends a GET request with http://localhost:3000/api/reset as the URL and the response code is 204(No Content), that means that the user has successfully deleted the users that are added by the users. If the user sends a GET request with http://localhost:3000/api/reset as the URL and the response code is 500(Internal Server Error ), that means that the request for reseting was unsuccessful because of some Internal Server Error.
